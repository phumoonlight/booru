# 2.3.0

## Changed

- **Export and import settings.** Two buttons on the settings screen write `save.json`
  to a file you choose and read it back — preferences and both sets of tag rules, as plain
  JSON with nothing secret in it. An import takes only the sections the file has and
  leaves the rest alone, and everything it changes takes effect at once rather than on the
  next launch.
- **Reach a post by number.** The `Post #15` heading in the editor is a box: type another
  number, press Enter, and you are there — whether or not the search behind it found that
  post. Escape puts the number back.
- **Back leads the editor's header**, with ◀️ ▶️ beside it, where the two used to be the
  other way round — the control that leaves was at the far end and the two that stay were
  at the start.
- **ℹ️ About rating stays at the top** of the upload screen instead of floating in the
  middle of an empty queue.
- **A tag's emoji is now a *mark*, and it can be a colour.** The box in front of a tag's
  name on the Tags screen takes an emoji as before, or a `#hex`, or a plain CSS colour
  name like `blue` — a colour is drawn as a dot. One per tag: a mark is the one thing in
  front of a name, and two of them would be read before the name they belong to. What you
  type is drawn beside the box as you type it. Every emoji already on a tag is kept.
- **The automatic colour dot is gone.** `blue_hair` used to get a blue dot from a list of
  colour words in the app, matched off the front of the name. It read `golden_retriever`
  as gold, had nothing to say about a colour the list had never heard of, and could not be
  corrected on the one tag it got wrong — a guess you cannot overrule is worse than no
  guess. Set the colour on the tag instead, and it is right everywhere, the website
  included.
- **About says when it is a development build.** A DEVELOPMENT tag beside the version on
  a checkout run with `desktop:dev`, and nothing at all on an installed copy — the two
  windows look identical, keep separate settings and rules, and the version a dev run
  reports is whatever the working tree currently says.
- **The tag categories are re-cut.** `head`, `exposure` and `posture` are gone, `sexual`
  is now `nsfw`, and `appearance`, `accessories` and `action` have arrived — a hair colour
  and an eye colour are both what someone looks like, `exposure` was `nsfw` under another
  name, and `posture` only ever held the standing-and-sitting half of what a subject is
  doing. Nothing is migrated for you: a tag still filed under an old name keeps working
  and stays searchable, but is drawn plain and sorted after the rest, which is how you
  find the ones left to move.
- **Tag rules live on the tag now.** The Tag rules item is gone from the header; click any
  tag on the Tags screen and its implications and recommendations are on the same panel as
  its name, category and count. A rule is written about a tag, so it is written where the
  tag is. The panel opens with the rules showing for a tag that has some, and 🔗 Rules
  folds them away.
- **Rules are picked from the grid, not typed.** Press 👆 Choose from the list and the tag
  list below becomes the picker: click a tag to tick it into the rule, click it again to
  take it off, ✅ Done or Escape to stop. While picking, the count column shows ✓ or ＋
  instead of a number. No more typing a name that was already on screen — and no more
  rules quietly built on a misspelling.
- **Tags and Browse have a toolbar.** 🔄 Refresh leads the row, the way a browser puts
  its reload beside the address bar, and the box beside it runs to the edge of the window
  — the search on Browse, and on Tags a new filter box that takes `blue archive` or
  `blue_archive`. New tag, Apply by tag and Rule map moved up onto the title line and lost
  their outlines.
- **🗺️ Rule map**, top right of the Tags screen: every rule on this machine at once, with
  implications drawn as the chains they actually make — `school_swimsuit →
  one-piece_swimsuit → swimsuit` is one shape rather than two rows to find separately. An
  implied rating floor sits on the tag that raises it. Every name is in its category's
  colour and behind its own emoji, and a rule naming a tag the board does not have is
  drawn plain and says so — it can never fire. Read-only; Escape closes it.
- **Small images are compressed far less.** The post image's AVIF quality now slides with
  its longer side — width for a landscape, height for a portrait, either for a square:
  quality 50 at 1920px and above, climbing steadily to 100 at 1280px and below (1600px
  gets 75, 1440px gets 88). An image that arrives at the size it will be looked at loses
  nothing to the downscale, so every artefact the encoder adds is one you see at 1:1;
  there was no reason to squeeze it as hard as a 4000px upload. Nothing gets bigger: an
  AVIF is still only stored when it beats the file you uploaded.
- **Browse draws two ways.** 🔳 Grid is the even columns it always was; 📐 Ratio gives
  every thumbnail the same height and its own width, nothing cropped, with whatever is
  left at the end of a line simply left there. The choice sticks while the app is open.
  The card is the same card either way — number and rating on their own strip under the
  picture — only its shape changes.
- **Browse opens where you left it.** The search you last ran and the posts it found are
  kept for a day, so starting the app puts the same grid back rather than an empty screen.
  🔄 Refresh reads the board again and throws the stored copy away, and an upload does the
  same by itself. The layout you chose is not kept, being a way of looking rather than
  something read from the board.
- **Thumbnails are kept on disk.** A thumbnail the app has drawn once is stored next to
  the other cached data and read from there instead of downloaded, so a grid you have seen
  before paints immediately — on a restart, and on a slow connection. They never go stale:
  a thumbnail's name is a fingerprint of the image itself, so a stored one is always the
  right picture, and deleting a post deletes its copy.
- **A tag's posts open in this window.** 🖼️ On the board on a tag's panel opened
  /tags/<id> in your browser, which answered "what is this tag on" somewhere that can only
  read. It is 🔍 Its posts now and goes to Browse with the tag already searched — the same
  question, answered where you can retag, re-rate or delete what it finds.
- **A header item you are already on stays there.** Pressing Browse while on Browse used
  to drop you back on the queue.
- **Buttons are drawn one way now**, everywhere in the window: an emoji, its words, no
  box, and a soft background under the pointer instead of an underline — an underline said
  "link", and these run searches and unfold panels. Real links, like the board URL in
  About, keep theirs. The 🔄 on Refresh fades while a read is in flight instead of
  spinning.

Your rules file is untouched — same `save.json`, same two sections, same behaviour while
tagging. Only where you edit them moved. One thing a rule can no longer do is name a tag
that does not exist yet; make it with ➕ New tag first, which is on the same screen.
